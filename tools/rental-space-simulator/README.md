# レンタルスペース収支シミュレーター

レンタルスペース事業(Javabronze とは別事業)の月次収支を、社長が自分で数字を変えて確かめるための道具。
依存なしの単一HTML。ネット接続もビルドも不要。

## 使い方

1. `index.html` をブラウザで開く(ダブルクリックでよい)
2. 左の入力欄を変えると、右側の結果がすぐに再計算される
3. 入力値はブラウザに保存される(`localStorage` のキー `rental-space-simulator:inputs:v3`)。「concept.md の初期値に戻す」で元に戻る。第3版でキーを変えたので、第2版の入力値は引き継がれない

スマホ幅では入力と結果が縦に並ぶ。ダークモードは端末の設定に従う。

## 計算式

営業時間(月)

- 1日の営業時間 `H = 閉店 − 開店`
- 平日昼 = 平日数 ×(夜の開始 − 開店)、平日夜 = 平日数 ×(閉店 − 夜の開始)、休日 = 休日数 × H
- 合計 = 月の日数 × H(初期値で 450時間)

月次収支

- 予約時間 = Σ(時間帯の営業時間 × 稼働率)
- 月売上 = Σ(時間帯の営業時間 × 稼働率 × 単価)
- 予約件数 = 予約時間 ÷ 平均利用時間
- 月利益 = 月売上 ×(1 − 手数料率)− 予約件数 × 清掃費 −(家賃 + その他固定費)
- 全体の稼働率 = 予約時間 ÷ 営業時間の合計
- 平均単価 = 月売上 ÷ 予約時間

損益分岐・回収

- 1時間あたりの貢献利益 `c = 平均単価 ×(1 − 手数料率)− 清掃費 ÷ 平均利用時間`
- 損益分岐稼働率 = 固定費 ÷ c ÷ 営業時間の合計
- 2年回収に必要な稼働率 =(固定費 + 初期投資 ÷ 24)÷ c ÷ 営業時間の合計
- 投資回収月数 = 初期投資 ÷ 月利益(赤字なら「回収不可」)
- 平均単価は今の時間帯の比率で決まる。つまり「平日昼・夜・休日の比率はそのままで、全体の稼働率だけが上下したら」という前提。予約0のときは営業時間の比率で重み付けする
- 「稼働率を変えたら」の表も同じ前提で、各時間帯の稼働率を同じ倍率で増減する(100%で頭打ち)

撤退基準の判定(concept.md 3-3 / 3-2)

| 時点 | 基準 |
|---|---|
| 3ヶ月 | 稼働率20%(目標) |
| 6ヶ月 | 20%未満で黄信号、30%+単月黒字が目標 |
| 見直し2回後 | 25%未満で撤退 |
| 12ヶ月 | 30%未満で撤退、40%で合格、45%で目標、50%超で上振れ(3ヶ月連続なら2室目検討) |
| 随時 | 運転資金が固定費3ヶ月分を割ったら撤退か縮小。赤字の場合は `(運転資金 − 固定費×3)÷ 月の赤字` ヶ月で到達 |

- 判定は「今の入力の稼働率が、その時点の実績だったら」で行う。月ごとの推移は扱わない
- 即時撤退(大家・行政からの是正要求)は数字で判定できないので対象外
- 金額はすべて税抜。消費税・所得税・減価償却は含まない

## テスト

```
node tools/rental-space-simulator/test.mjs
```

`index.html` の `<script id="calc">`(計算ロジック)を取り出して Node で評価し、concept.md と market-report.md の試算(損益分岐27%、2年回収44%、家賃+1万円で+1.7ポイント、6ヶ月・12ヶ月の目標など)と照合する。計算ロジックを変えたら必ず実行すること。

注意:concept.md 3-2 の「開業3ヶ月:月の営業損益 約−4万円」は、同じ表の計算式(売上 × 0.7 − 清掃費 − 固定費16万円)で計算すると約−6万円になる。テストは計算式のほうに合わせている。
