## 1. KPIツリー

```
月の営業利益
├─ 手取り売上 = 売上 ×(1 − 手数料率)
│   ├─ 売上 = 予約時間 × 平均単価
│   │   ├─ 予約時間 = 510h × 稼働率
│   │   │   ├─ 早朝の稼働率(90h枠)…… 承認制。前夜22時までに終わる日だけ(concept 2-4)
│   │   │   ├─ 平日昼の稼働率(168h枠)… 平日休みの推し活・昼飲み、撮影・会議(副次)
│   │   │   ├─ 平日夜の稼働率(126h枠)… 晩酌3hパック、上映会4hパック
│   │   │   └─ 土日祝の稼働率(126h枠)… 推し活5hパック、晩酌4hパック
│   │   │       └─ 共通の先行指標:ポータル閲覧数 → 予約転換率、レビュー件数・平均点、リピート率
│   │   └─ 平均単価 = 時間帯ミックス × 各帯の単価  ← 2,700円は「土日祝75%・平日夜55%」が前提
│   └─ 手数料率 = ポータル別の売上構成(SM 30% / IB 35% / 直接 0%)
├─ 清掃費 = 予約件数 × 1回単価(1,500円)
│   └─ 予約件数 = 予約時間 ÷ 1予約あたりの平均時間(4h)  ← 3hに縮むと清掃+500円と同じ悪化
└─ 固定費 11.5万円(家賃が61%)
```

## 4. 注意点(第3版で新たに見えたこと)

1. **平均単価2,700円は「土日祝75%・平日夜55%」が埋まる前提**。時間帯別の実効単価(早朝1,000/平日昼1,450/平日夜2,550/土日祝3,350円)で見ると、全体40%のうち平日昼が19%程度にとどまり、単価の高い枠がよく埋まったときに平均約2,700円になる(`band-mix.csv`)。平日昼が35%まで埋まり、土日祝が55%にとどまるミックスだと、平均は約2,430円に下がる。**平日昼を埋めるほど平均単価は下がる**ので、稼働率と単価は別々に見ず、時間帯別の稼働率で追う。
2. **12ヶ月回収の余裕は「単価で約100円、稼働率で約1pt」しかない**。家賃7万円・12ヶ月目40%なら、12ヶ月回収に必要な単価は2,600円(`payback-grid.csv`)。12ヶ月目の稼働率が38%(ランプ全体を比例して下げた場合)なら13ヶ月目になる。どのレバーも1つ外れるだけで13ヶ月目以降になる(`levers.csv`)。
3. **手数料の消費税**:免税事業者で手数料の消費税分を差し引けないと実質33%になり、12ヶ月累積が約14万円減って13ヶ月目回収になる。インスタベース(35%)中心だと約23万円減る。
4. **1予約が3時間に縮むと、清掃+500円と同じだけ悪化する**(12ヶ月累積 −21.7万円)。晩酌3hパックが中心になると起きやすいので、1予約あたりの時間を週次で追う。
5. 季節変動は入れていない。推し活のイベント時期と晩酌の週末集中で、月ごとの稼働率は上下する。

## 5. 利用データの計測(ai-ceo への提案)

- 実績がゼロなので、上の目安はすべて仮定。開業後すぐに「ポータル別の予約CSVを週1回ダウンロード → 1つの表に統合 → **時間帯4区分(早朝を含む)**の稼働率と平均単価を出す」仕組みが要る(concept 第8章の ai-programmer の集計スクリプト)。**開業前に作っておくことを推奨**。
