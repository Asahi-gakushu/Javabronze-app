### 1-2. 清掃・点検チェックリスト(毎回)

所要時間の目安は20〜30分(concept.md の30分バッファ内)。利用者がゴミ出しと片付けをする前提で、**1回1,500円**で委託できる範囲にする。

1. 入室前に室内の写真を撮る(破損・汚損・ゴミの残りの証拠)
2. 室内に残ったゴミの確認。残っていれば回収・分別してゴミ置き場へ出し、**写真を撮って「ゴミ残りあり」で報告**(追加清掃費の根拠。1-6)。ゴミ置き場に前の利用者の分別違反・放置がないかも見る
3. テーブル・椅子・リモコン・ドアノブの拭き掃除、床の掃除機がけ
4. トイレ・洗面所(ある場合)の清掃と、トイレットペーパー・ハンドソープの補充
5. 家具を標準配置(**晩酌・シアター配置が基本**。会議の予約の前だけ会議配置。ai-designer の配置図)に戻す
5-2. **換気と消臭**(窓を開ける・空気清浄機を強運転・布製品に消臭スプレー)。晩酌の匂いが次の撮影・会議の利用者に残らないように(concept.md 1-4)
5-3. 冷蔵庫の中に飲み物・食べ物が残っていないか、電子レンジの中の汚れ
6. プロジェクター・サウンドバー・照明・空調の電源オフ、リモコンの所定位置
7. 装飾キットの数と破損の確認、装飾の剥がし残し(テープ跡)の確認、グラス・食器の数と洗浄
8. 窓の施錠、忘れ物の確認(保管ルールは第1-4章)、ゴミ袋(4分別)の補充
9. 清掃後の写真を撮り、報告フォームに送る(A6)
10. 次の予約までの時間が短い場合は、社長に「清掃完了」を連絡

### 1-4. トラブル時の対応

**共通ルール**
- 近隣・大家・管理会社・ゲストへの連絡は**社長が行う**(AI社員は文面の下書きまで)
- 発生日時・内容・対応・写真を「トラブル記録簿」(非公開スプレッドシート)に残す。個人情報を除いた要約を ai-secretary が月次議事録に載せる
- 身体の危険・火災・犯罪の疑いがあるときは、まず 110番 / 119番。その後に社長へ

| 事象 | 初動(目安の時間) | その後 |
|---|---|---|
| **騒音苦情(近隣・管理会社から)** | 15分以内にゲストへポータルのメッセージで音量を下げるよう依頼(定型文)。改善しなければ電話等で直接伝え、ハウスルール違反として退室を求めることも検討 | 苦情元へ社長がお詫びと対応内容を連絡。センサーのログ・時刻を記録。同じゲストは次回以降お断り。繰り返す場合は用途・時間帯の制限(夜の晩酌パックの縮小など)を検討。**書面の是正要求を受けたら concept.md 3-5 の撤退基準で判定** |
| 騒音センサーのしきい値超過(苦情前) | concept.md 1-5 の3段階:①自動メッセージ ②ホストから電話 ③退室を求め、違約金(返金なし)。22:00以降はしきい値を下げる | 記録。頻発する時間帯・用途は掲載文とルールを見直す |
| 泥酔・20歳未満の飲酒・嘔吐 | 泥酔者は入室を断る。20歳未満の飲酒はその場で退室を求める。体調が悪そうなら119番 | 嘔吐は追加清掃費2万円(concept.md 1-5 の7)。記録して次回以降お断り |
| **破損・汚損** | 清掃担当が写真を撮って報告。使えない設備は次の予約前に代替手段を用意し、影響するゲストに事前連絡 | ポータルの補償・保険の手続き(期限に注意)。ゲストへの請求はポータルの規定に沿って行う。修理費と保険金は costs.md に記録 |
| 入れない(鍵の不具合・暗証番号の誤り) | 社長が遠隔で解錠 または 番号を再発行。できなければ予備の物理鍵の手順(キーボックス等) | 原因の記録。電池切れ防止のため電池交換を定期化 |
| 利用時間の超過・無断延長 | 退室時刻に定型文で連絡 | ポータルの延長料金の規定に沿って対応 |
| 定員超過・無断の宿泊・深夜滞在 | 定型文で退室を依頼 | 旅館業法の観点から放置しない。記録して次回以降お断り |
| 設備の故障(空調・プロジェクター・Wi-Fi) | ゲストに簡単な復旧手順(再起動等)を案内 | 修理・交換。影響があれば返金・減額をポータルの規定に沿って判断(社長) |
| 忘れ物 | 清掃担当が写真付きで報告し、室内の所定の箱で保管 | ゲストへ連絡。保管期間(例:1か月)と返送方法(着払い等)をハウスルールに明記 |
| ゴミの放置・分別違反・大量のゴミ | 写真で記録(1-6) | 追加清掃費3,000円の請求可否をポータル規定で確認。ゴミ置き場の場合は管理会社への連絡も検討(社長) |

### 1-5. レビュー返信のルール

1. 投稿から3日以内に返信する(ai-writer が下書き → 社長が確認して投稿)
2. 良いレビュー:お礼+具体的に触れられた点への一言+次回の利用提案(平日昼・パック料金など)
3. 低評価・苦情のレビュー:反論しない。事実の確認とお詫び、改善内容を簡潔に書く。ゲストの個人情報やルール違反の詳細は書かない
4. 指摘された改善点は ai-secretary がトラブル記録簿とは別の「改善リスト」に登録し、月次で消化状況を確認

### 1-6. ゴミ出しを利用者が行う運用と、退室時の確認方法

concept.md 1-7 のとおり、**利用者が自分で分別し、建物の24時間ゴミ置き場へ捨てに行く**。分別できない物・大量のゴミ(段ボール多数、瓶のケースなど)は持ち帰ってもらう。

**利用者の流れ(入室案内・退室チェックリストの本文は ai-writer が作る)**

| 時刻(夜の枠) | 利用者がすること |
|---|---|
| 22:00 | 静音タイム(サウンドバーの上限が自動で下がる) |
| 22:30 | 飲酒終了。片付け開始(缶・瓶・ペットボトルを軽くすすぐ、燃やすゴミを袋にまとめる) |
| 22:45まで | 4分別の袋をゴミ置き場へ出す(入室案内の写真付きの道順どおりに。共用部では静かに) |
| 22:45〜23:00 | 退室チェックリストを確認し、退室写真を撮って送る → 23:00までに退室 |

- 夜以外の枠は「退室の30分前に片付け開始、15分前までにゴミ出し」とする
- 早朝枠(6〜9時)は飲酒不可なので、ゴミは少ない想定。ゴミ置き場が6時台に使えることを内見時に確認する(viewing-checklist.md G2)

**退室時の確認方法(4つを組み合わせる)**

| # | 方法 | 何が分かるか | 担当 |
|---|---|---|---|
| 1 | **退室写真の提出**:①室内全体 ②空になったゴミ箱の中 ③ゴミ置き場に出した袋(**他の人・他社のゴミの中身や表示が写らないように**)④照明・プロジェクターの電源オフ。報告フォーム(A13)またはポータルのメッセージで送ってもらう | ゴミ出しと片付けが済んだか | 利用者 → 社長が確認 |
| 2 | **スマートロックの施錠ログ・入口カメラ**:退室時刻と、ゴミ袋を持って出入りしたか(入口カメラは部屋の入口付近のみ。共用部とゴミ置き場は撮らない) | 23:00までに退室したか | 自動 → 社長 |
| 3 | **清掃担当の入室時チェック**(1-2 の手順2):室内のゴミの残り・分別違反を写真で報告 | 写真と実態が合っているか | 清掃担当(開業1〜2ヶ月は社長) |
| 4 | **ゴミ置き場の定期確認**:清掃のたびにゴミ置き場を見て、分別違反・溢れ・放置がないか確認 | 建物側からの苦情の芽 | 清掃担当 |

**確認後の対応**

| 状況 | 対応 |
|---|---|
| 退室写真が届かない | 退室10分後に定型文で依頼。翌朝までに届かなければ清掃担当の報告で判断 |
| 室内にゴミが残っていた/分別違反・ゴミ置き場への放置 | 写真で記録し、ハウスルールの追加清掃費(分別違反・放置 3,000円)をポータルの規定に沿って請求するか社長が判断。繰り返す利用者は次回以降お断り |
| 管理会社・他テナントからゴミの苦情 | 社長が当日中にお詫びと是正(清掃担当が回収・分別し直す)。発生日時と予約を照合して記録。**書面の是正要求は concept.md 3-5 の撤退基準で判定** |
| 利用者が退室時刻までにゴミを出せなかった | 室内の分別ゴミ箱に置いてもらい、清掃担当が出す。回数が多い場合は案内文(22:30の片付け開始)を見直す |

### 1-7. 早朝枠(6〜9時)の承認手順

concept.md 2-4 のとおり。

1. 早朝枠は**承認制**で、**前々日までの予約のみ**受け付ける(ポータルのリクエスト予約の設定)
2. 承認の条件:**前の夜の予約が22:00までに終わる日**だけ(22:00〜22:30に清掃)。前の夜に22時以降の予約がある場合は、単価の高い夜を優先して早朝枠は断る
3. 前の夜の最後の利用が23:00に終わる日は、翌朝の早朝枠を売らない(清掃は翌日9時以降の最初の予約の前)
4. 承認後、夜の枠に22:00以降の予約が入らないよう、カレンダーでその夜の22:00〜23:00をブロックする(A2)
5. 早朝枠は飲酒不可。事前案内にも明記する
6. 目標稼働率は10%(分母90時間)。早朝で稼ぐのではなく「朝から使える部屋」という選ばれる理由を増やすのがねらい

### 2-3. ゴミの扱い

- **利用者が分別して建物の24時間ゴミ置き場に出す**(運用は 1-6)。分別できない物・大量の物は持ち帰り
- 利用者のゴミは事業系ゴミとして扱われ、地域の家庭ゴミ集積所には出せない可能性が高い【要確認:ai-researcher・自治体】。家庭ゴミ集積所しかない物件は契約しない(viewing-checklist.md G1〜G5)
- ビルの事業系ゴミ処理費(計画 月5,000円)は costs.md 第2章に記録する
- 室内には4分別のゴミ箱と、分別方法・ゴミ置き場の道順を示す掲示を置く(掲示の本文は ai-writer、デザインは ai-designer)

## 3. 自動化案(Zapier の代替)

### 3-1. 方針

- **正本(マスター)は Google スプレッドシート「予約台帳」と Google カレンダー「運営カレンダー」**(事業用Googleアカウント・非公開)
- 仕組みは **Google Apps Script(GAS)** を中心に作る。Googleアカウント内で動き、追加費用がかからない
- **GitHub Actions は個人情報を扱わない処理だけ**に使う(集計済みの匿名データ、リンク切れチェック等)。ゲスト情報をリポジトリやActionsのログに出さない
- 予約の一元管理・ダブルブッキング防止は、ポータル側に外部カレンダー連携(iCal等)があるかで方式が変わる。**各ポータルの連携機能の有無は【未確認】**。連携できない場合は「通知メールを読み取り → 他ポータルを手動でブロック」の半自動運用にする。複数ポータルに対応した有料の一元管理サービスを使う場合は、費用と対応ポータルを ai-admin が比較し社長が判断する
- ゲストへのメッセージ送信・清掃担当への通知など**外部に送る自動化は、文面と宛先を社長が承認してから有効化**する。最初の2週間は「下書きを作る → 社長が送信」の運用で試す

### 3-2. 自動化の一覧

| ID | 自動化 | きっかけ | 処理 | ツール | 段階 |
|---|---|---|---|---|---|
| A1 | 予約の取り込み | ポータルからの予約確定メール(Gmail) | 件名・本文から ポータル名・日時・時間・金額・予約番号 を抽出し「予約台帳」に1行追加。個人名は台帳のみに保存 | GAS(Gmailの時間主導トリガーで10分ごと) | 開業前に作る |

### 3-3. 導入の順番

1. 事業用Googleアカウントの作成(社長)→ 予約台帳・運営カレンダー・報告フォームを用意(ai-admin が設計、社長が作成または権限付与)
2. A1・A2・A7 を作り、テスト予約で動作確認(ダブルブッキング警告が出るか)
3. A3・A6 を作る。清掃担当への通知は社長の承認後に有効化
4. A4 は「下書きを社長に届ける」形で開始し、2週間運用して文面を固める
5. A9〜A11 は開業後に追加
6. GAS のスクリプト本体は、APIキー・メールアドレス・暗証番号を含めない形でのみリポジトリに置いてよい(設定値はGAS の「スクリプト プロパティ」に保存)

### 3-4. 自動化で気をつけること

- ポータルの予約メールの書式が変わると A1 が止まる。A7 の日次サマリーで「取り込み件数0件が3日続いたら警告」を出す
- 自動化が止まっても運営できるよう、社長は毎朝ポータルの管理画面も確認する(開業後3か月は必須)
- ゲストの個人情報は利用目的の範囲で扱い、保存期間を決めて古いデータを削除する(例:税務上必要な売上記録を除き1年)【要確認:個人情報保護法の対応は専門家に確認】
