# レンタルスペース 運営フローと自動化案(初版)

- 作成:ai-admin / 作成日:2026-09-26
- 前提:concept.md の運営方針(無人運営、スマートロック+防犯カメラ+騒音センサー、清掃外注、営業8〜23時、パーティー系は22時退室、定員6名、利用後30分は清掃バッファ)
- 利用者向けの文章(入室案内・ハウスルール・退室チェックリスト・レビュー依頼・返信文)の本文は ai-writer が作る。本書は「いつ・誰が・何をするか」の手順を定める
- ゲストの氏名・連絡先・暗証番号などの個人情報は**このリポジトリに書かない・コミットしない**。記録は事業用のGoogleスプレッドシート等(非公開)で行う

## 1. 運営フロー

### 1-1. 予約ごとのフロー

| タイミング | 作業 | 担当 | 仕組み化(第3章) |
|---|---|---|---|
| 予約確定時 | 予約内容を一元管理シートとカレンダーに登録。他ポータルの同じ枠をブロック(ダブルブッキング防止) | 自動(A1・A2)/ 社長が確認 | ○ |
| 予約確定時 | 利用目的・人数がハウスルールに合うか確認(定員6名超、深夜・宿泊目的、大音量・大人数パーティーの疑い) | 社長 | 疑わしい予約は社長判断で、ポータルの規定に沿ってお断り・確認 |
| 予約確定時 | 清掃予定をカレンダーに作成し、清掃担当に通知 | 自動(A3) | ○ |
| 利用3日前 | 事前案内(アクセス、ハウスルール、ゴミの扱い、22時退室、騒音ルール) | 定型文(A4) | ○(送信はポータルのメッセージ機能) |
| 利用前日〜当日朝 | スマートロックの暗証番号(利用時間のみ有効)を発行し、入室案内を送る | 社長 または 自動(A5) | △(製品による) |
| 利用開始時 | 入室の確認(スマートロックの解錠ログ) | 自動通知 → 社長 | ○ |
| 利用中 | 騒音センサーのしきい値超過を監視。超過時は第1-4章の手順 | 自動通知 → 社長 | ○ |
| 退室15分前 | 退室案内(退室チェックリスト、ゴミ、延長の可否) | 定型文(A4) | ○ |
| 退室後 | 解錠ログで退室確認。暗証番号の失効を確認 | 自動 → 社長 | ○ |
| 退室後30分以内 | 清掃・点検(第1-2章)。破損・忘れ物・ルール違反があれば写真を撮って報告 | 清掃担当 | 報告フォーム(A6) |
| 退室後1〜2日 | お礼とレビュー依頼 | 定型文(A4) | ○ |
| レビュー投稿後3日以内 | レビュー返信(第1-5章) | ai-writer(下書き)/ 社長(投稿) | 下書きのみ |

### 1-2. 清掃・点検チェックリスト(毎回)

所要時間の目安は20〜30分(concept.md の30分バッファ内)。

1. 入室前に室内の写真を撮る(破損・汚損の証拠)
2. ゴミの回収・分別(自治体・建物のルールに従う。事業ごみの扱いは第2-3章)
3. テーブル・椅子・リモコン・ドアノブの拭き掃除、床の掃除機がけ
4. トイレ・洗面所(ある場合)の清掃と、トイレットペーパー・ハンドソープの補充
5. 家具を標準配置(平日昼は会議配置、それ以外はシアター配置。ai-designer の配置図)に戻す
6. プロジェクター・サウンドバー・照明・空調の電源オフ、リモコンの所定位置
7. 装飾キットの数と破損の確認、装飾の剥がし残し(テープ跡)の確認
8. 窓の施錠、忘れ物の確認(保管ルールは第1-4章)
9. 清掃後の写真を撮り、報告フォームに送る(A6)
10. 次の予約までの時間が短い場合は、社長に「清掃完了」を連絡

### 1-3. 日次・週次・月次の定常業務

| 頻度 | 作業 | 担当 |
|---|---|---|
| 毎日(朝) | 当日の予約・清掃予定の確認、スマートロック・カメラ・センサーのオンライン状態の確認、ポータルのメッセージ確認 | 社長(自動の日次サマリーを見る、A7) |
| 毎日(夜) | 当日の苦情・トラブルの有無、未返信メッセージの確認 | 社長 |
| 週1回 | 消耗品の在庫確認と発注、スマートロックの電池残量確認、週次KPI(稼働率・予約数・レビュー) | 社長 / ai-analyst |
| 月1回 | 深い清掃(空調フィルター、換気扇、壁の汚れ、プロジェクターのレンズ)、備品の劣化確認、消火器の外観点検 | 清掃担当 または 社長 |
| 月1回 | 経費の締め、売上・手数料の突合(costs.md)、価格の見直し(concept.md 2-3) | ai-admin(集計)/ ai-analyst / 社長 |
| 四半期 | 保険・契約・ポータル規約の変更確認、撤退基準の判定 | ai-admin / ai-ceo / 社長 |

### 1-4. トラブル時の対応

**共通ルール**
- 近隣・大家・管理会社・ゲストへの連絡は**社長が行う**(AI社員は文面の下書きまで)
- 発生日時・内容・対応・写真を「トラブル記録簿」(非公開スプレッドシート)に残す。個人情報を除いた要約を ai-secretary が月次議事録に載せる
- 身体の危険・火災・犯罪の疑いがあるときは、まず 110番 / 119番。その後に社長へ

| 事象 | 初動(目安の時間) | その後 |
|---|---|---|
| **騒音苦情(近隣・管理会社から)** | 15分以内にゲストへポータルのメッセージで音量を下げるよう依頼(定型文)。改善しなければ電話等で直接伝え、ハウスルール違反として退室を求めることも検討 | 苦情元へ社長がお詫びと対応内容を連絡。センサーのログ・時刻を記録。同じゲストは次回以降お断り。繰り返す場合は用途・時間帯の制限(パーティー枠の縮小)を検討。**書面の是正要求を受けたら concept.md 3-3 の撤退基準で判定** |
| 騒音センサーのしきい値超過(苦情前) | 5分継続したら自動通知 → 社長が定型文で注意 | 記録。頻発する時間帯・用途は掲載文とルールを見直す |
| **破損・汚損** | 清掃担当が写真を撮って報告。使えない設備は次の予約前に代替手段を用意し、影響するゲストに事前連絡 | ポータルの補償・保険の手続き(期限に注意)。ゲストへの請求はポータルの規定に沿って行う。修理費と保険金は costs.md に記録 |
| 入れない(鍵の不具合・暗証番号の誤り) | 社長が遠隔で解錠 または 番号を再発行。できなければ予備の物理鍵の手順(キーボックス等) | 原因の記録。電池切れ防止のため電池交換を定期化 |
| 利用時間の超過・無断延長 | 退室時刻に定型文で連絡 | ポータルの延長料金の規定に沿って対応 |
| 定員超過・無断の宿泊・深夜滞在 | 定型文で退室を依頼 | 旅館業法の観点から放置しない。記録して次回以降お断り |
| 設備の故障(空調・プロジェクター・Wi-Fi) | ゲストに簡単な復旧手順(再起動等)を案内 | 修理・交換。影響があれば返金・減額をポータルの規定に沿って判断(社長) |
| 忘れ物 | 清掃担当が写真付きで報告し、室内の所定の箱で保管 | ゲストへ連絡。保管期間(例:1か月)と返送方法(着払い等)をハウスルールに明記 |
| ゴミの放置・大量のゴミ | 写真で記録 | ハウスルールに基づく追加料金の請求可否をポータル規定で確認 |

### 1-5. レビュー返信のルール

1. 投稿から3日以内に返信する(ai-writer が下書き → 社長が確認して投稿)
2. 良いレビュー:お礼+具体的に触れられた点への一言+次回の利用提案(平日昼・パック料金など)
3. 低評価・苦情のレビュー:反論しない。事実の確認とお詫び、改善内容を簡潔に書く。ゲストの個人情報やルール違反の詳細は書かない
4. 指摘された改善点は ai-secretary がトラブル記録簿とは別の「改善リスト」に登録し、月次で消化状況を確認

## 2. 備品・消耗品の管理

### 2-1. 常備する消耗品(初期購入リスト)

| 品目 | 補充の目安 |
|---|---|
| ゴミ袋(可燃・不燃・資源) | 在庫が1週間分を切ったら |
| トイレットペーパー、ハンドソープ、ティッシュ | 同上 |
| 除菌シート、アルコールスプレー、清掃用洗剤、雑巾 | 同上 |
| 掃除機の紙パック/フィルター | 月1回確認 |
| 養生テープ・マスキングテープ(装飾用に貸出) | 週1回確認 |
| リモコン・スマートロック・センサー用の乾電池 | 月1回確認、スマートロックは残量警告で交換 |
| 消火器 | 設置位置と使用期限を月1回確認 |

### 2-2. 貸出備品(装飾キット・撮影用品など)の台帳

非公開スプレッドシートに「品名・数量・購入日・購入価格・状態」で管理する。10万円以上のものは costs.md の固定資産台帳にも載せる。

### 2-3. ゴミの扱い

- 事業から出るゴミは、家庭ごみの集積所に出せない場合が多い【要確認:自治体と建物の規則】。事業系ゴミの収集契約か、清掃担当による持ち帰り・処理の方法を開業前に決める
- ゲストにはゴミの分別・持ち帰りのルールを事前案内で伝える

## 3. 自動化案(Zapier の代替)

### 3-1. 方針

- **正本(マスター)は Google スプレッドシート「予約台帳」と Google カレンダー「運営カレンダー」**(事業用Googleアカウント・非公開)
- 仕組みは **Google Apps Script(GAS)** を中心に作る。Googleアカウント内で動き、追加費用がかからない
- **GitHub Actions は個人情報を扱わない処理だけ**に使う(集計済みの匿名データ、リンク切れチェック等)。ゲスト情報をリポジトリやActionsのログに出さない
- 予約の一元管理・ダブルブッキング防止は、ポータル側に外部カレンダー連携(iCal等)があるかで方式が変わる。**各ポータルの連携機能の有無は【未確認】**。連携できない場合は「通知メールを読み取り → 他ポータルを手動でブロック」の半自動運用にする。複数ポータルに対応した有料の一元管理サービスを使う場合は、費用と対応ポータルを ai-admin が比較し社長が判断する
- ゲストへのメッセージ送信・清掃担当への通知など**外部に送る自動化は、文面と宛先を社長が承認してから有効化**する。最初の2週間は「下書きを作る → 社長が送信」の運用で試す

### 3-2. 自動化の一覧

| ID | 自動化 | きっかけ | 処理 | ツール | 段階 |
|---|---|---|---|---|---|
| A1 | 予約の取り込み | ポータルからの予約確定メール(Gmail) | 件名・本文から ポータル名・日時・時間・金額・予約番号 を抽出し「予約台帳」に1行追加。個人名は台帳のみに保存 | GAS(Gmailの時間主導トリガーで10分ごと) | 開業前に作る |
| A2 | 運営カレンダーへの登録と重複チェック | A1 の行追加 | 利用時間+前後30分の清掃バッファで予定を作成。既存予定と重なれば社長にメールで警告(ダブルブッキング) | GAS + Googleカレンダー | 開業前 |
| A3 | 清掃スケジュールの作成と通知 | A2 の予定作成 | 退室時刻〜30分の「清掃」予定を作り、清掃担当のカレンダーに招待(またはメール通知)。キャンセル時は自動で削除・通知 | GAS + Googleカレンダー | 開業前(外部通知は社長承認後に有効化) |
| A4 | 定型メッセージの準備 | 予約日時からの相対時刻(3日前・退室15分前・退室翌日) | ai-writer の定型文に日時・部屋情報を差し込み、社長宛てに「送信用の下書き」をメールで届ける。**送信はポータルのメッセージ機能から社長が行う**(ポータル外での直接連絡は規約違反の可能性があるため) | GAS | 開業前。ポータルに予約メッセージの自動送信機能があればそちらを優先【未確認】 |
| A5 | スマートロックの暗証番号発行 | 予約確定 | 利用時間のみ有効な番号を発行。予約管理と連携できる製品なら自動、できなければ社長が手動で発行 | スマートロックのアプリ/API(製品選定で決定) | 製品選定時に判断 |
| A6 | 清掃・破損の報告 | 清掃完了時 | Googleフォーム(写真・チェック項目・破損有無)→ スプレッドシート。破損「有」なら社長へ即時メール | Googleフォーム + GAS | 開業前 |
| A7 | 日次サマリー | 毎朝7時 | 当日の予約・清掃予定・未完了の清掃報告・スマートロック電池警告を社長にメール | GAS | 開業前 |
| A8 | 騒音・入退室アラート | センサー・スマートロックの通知 | しきい値超過・解錠をスマートフォンに通知。ログは月次でトラブル記録と照合 | 各機器のアプリ通知(製品選定で決定) | 開業前 |
| A9 | 週次KPIの集計 | 毎週月曜 | 予約台帳から稼働率・平均単価・時間帯別・ポータル別を集計し、別シートに出力。**個人情報を除いた集計CSV**をダウンロードできる状態にする | GAS(または ai-programmer の集計スクリプト) | 開業後1か月以内 |
| A10 | 月次の経費締めリマインド | 毎月1日 | 「前月の領収書・ポータルの売上明細を保存したか」のチェックリストを社長にメール | GAS または Googleカレンダーの繰り返し予定 | 開業前 |
| A11 | 更新期限のリマインド | 期限の30日前 | 保険・契約・ドメイン等の更新期限を通知 | Googleカレンダーの繰り返し予定 | 開業後1週間以内 |
| A12 | リポジトリ内の文書チェック | `docs/rental-space/` の変更時 | Markdownのリンク切れ・表の崩れ・秘密情報らしき文字列(メールアドレス・電話番号の形)の検出 | GitHub Actions | 任意(Javabronze の CI に追加する場合は ai-programmer と調整) |

### 3-3. 導入の順番

1. 事業用Googleアカウントの作成(社長)→ 予約台帳・運営カレンダー・報告フォームを用意(ai-admin が設計、社長が作成または権限付与)
2. A1・A2・A7 を作り、テスト予約で動作確認(ダブルブッキング警告が出るか)
3. A3・A6 を作る。清掃担当への通知は社長の承認後に有効化
4. A4 は「下書きを社長に届ける」形で開始し、2週間運用して文面を固める
5. A9〜A11 は開業後に追加
6. GAS のスクリプト本体は、APIキー・メールアドレス・暗証番号を含めない形でのみリポジトリに置いてよい(設定値はGAS の「スクリプト プロパティ」に保存)

### 3-4. 自動化で気をつけること

- ポータルの予約メールの書式が変わると A1 が止まる。A7 の日次サマリーで「取り込み件数0件が3日続いたら警告」を出す
- 自動化が止まっても運営できるよう、社長は毎朝ポータルの管理画面も確認する(開業後3か月は必須)
- ゲストの個人情報は利用目的の範囲で扱い、保存期間を決めて古いデータを削除する(例:税務上必要な売上記録を除き1年)【要確認:個人情報保護法の対応は専門家に確認】
